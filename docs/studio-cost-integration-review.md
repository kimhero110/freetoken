# Studio 成本融合方案与重构评审

日期：2026-09-06。状态：修订设计，未实施、未部署。

依据：用户明确要求成本功能主要体现在 WitKit Studio；复核了本仓库 `_websit/server-current` 内保存的 Studio 源码。该目录是服务器快照，本次未重新拉取线上版本；实施前应比对实际部署，并建立唯一可维护源码目录，不能直接将快照当开发主线。

## 1. 对上一版方案的修正

保留精确计费、版本化报价、未知状态、黄金算例、证据分层与可复算原则。修正三点：

1. 完整计算、比较、实测报告都归 Studio；主站承担平台发现、报价规则解释和进入工具的入口。
2. 成本是评测的横向分析能力，不是强制增加一个会发请求的第16项测试，也不直接加入原有质量总分。
3. 现有 Studio 是 Python，主站无需本地正式计算后，优先用 Python Decimal 纯函数包作为唯一生产成本引擎。无需为了前后端共用而先引入 Node 调用桥；前端通过 Studio 同源接口获取结果。Decimal 精度、舍入和单位仍需显式定义，不能只替换数字类型。

## 2. 页面与用户路径

Studio 使用同一工作台，顶层提供“预算估算”“质量评测”“综合分析”三种模式，共用报价选择、业务用量和报告组件。

- `/cost`：默认预算估算，不需要 Key、不执行模型调用。选择报价和业务用量，查看月预算与方案比较。
- `/`：保留现有质量评测入口与快速/深度预设；统一接入点表单，并能切换综合分析。
- `/report/{id}`：统一报告，包含质量、性能、本次调用用量及费用、可选业务预算、证据与限制。
- `/compare`：第二阶段提供同模型、多方案的并排比较。优先比较静态报价，不自动对全部端点跑测试。

预算模式隐藏接入凭据字段。质量模式不强迫用户填写月预算。综合模式可填写业务用量，同时复用原有测试调用产生的观测。无报价时仍能完成质量测试，费用显示未知；无Key时仍能计算预算。

主站导航“成本与评测”进入 Studio；平台详情展示免费额度、资格和报价来源，提供“估算成本”“评测接口”两个按钮。首页以找平台→算预算→看评测解释流程，不建立第二个工具后台。

跳转示例（拟议契约）：`https://test.witkit.zone/cost?platform=deepseek&offer_id=example-offer&mode=estimate&from=platform`。参数只带公开稳定标识和模式；目标端查验报价并展示实际匹配结果，不信任URL里的金额。没有有效报价时引导选报价或自填，不悄悄换成另一平台报价。

现有主站 `/cost/` 上线初期保留说明和跳转入口，确认新页等价可用后再设置带允许列表参数映射的重定向。既有分享链接、语言路径单独迁移。主站不接收Key；不跨域传Key、任务访问令牌、私有报告链接或原始用量。先不引入统一登录和第三个域名。

## 3. 现有代码中需要先改的接缝

| 文件 | 已观察到的结构 | 改造 |
|---|---|---|
| bench/client.py | 统一chat入口，只汇总requests/prompt/completion，缺失值归零 | 增加逐请求观测和缺失状态；区分模型列表请求与推理请求；保留缓存和推理字段来源 |
| bench/tests/concurrency.py | 多线程共用Client | 观测写入和预算预留必须线程安全；每个请求独立ID，不能只靠可变全局计数 |
| bench/runner.py | 依序执行测试，结束时汇总usage与评分 | 注入run_id/test_id上下文，测试结束后独立调用成本分析；费用失败不抹去测试结果 |
| server_bench.py | 请求线程内执行，NDJSON进度；runner和handler均发done | 运行状态与传输分离，持久化后只发送一个最终done；断连后可查询任务 |
| bench/store.py | SQLite保存整份报告，最新500条自动清理 | 增加schema版本、观测记录、成本分析修订与访问控制；保留策略和删除关联记录明确化 |
| bench/pages.py、ui.py | 当前质量报告和历史列表 | 增加费用、覆盖率、业务预算和可比性；旧报告兼容“成本数据不足” |

现有字符长度推算Token的测试指标只能保留为性能估计，不能伪装成厂商计费用量。历史报告只有汇总usage时，不重建不存在的逐请求事实。

## 4. 统一执行与采集

建立 RunPlan，包含mode、test_ids、接入配置引用、报价快照、可选业务用量、调用次数/输出规模限制。先展示将运行的测试和额外请求，再执行用户选择。

每次实际请求产生不可变 CallObservation：run_id、test_id、call_id、请求类型、时间、模型、状态、标准化usage、usage来源与完整性、可解释的网关自报费用、适配器版本。敏感凭据只由短生命周期任务上下文持有，不进入持久化对象。

质量评分和成本分析分别消费同一批观测。测试失败仍可能产生费用，不能按ok过滤掉；网络超时无法判断扣费则保留未知。零输出、usage缺失、流式中断和无最终usage必须分别处理。

优先零新增调用采集现有测试的用量。流式usage通过已验证适配器请求或解析；不兼容时标缺失，不自动重发计费请求。某项需要独立计费样本时，在RunPlan标明额外调用，用户选择后执行，不后台补测。

两类覆盖率分别报告：推理请求中返回完整usage的比例、观测计费维度有报价覆盖的比例。不能以“请求覆盖率80%”推断“费用只差20%”。缺失必要维度时给已知小计，完整总价为unknown。

执行层首先用受限worker和持久化任务状态，保持现有NDJSON展示协议；连接是观察渠道，不是任务本身。断连不重跑任务；取消停止尚未开始的请求并尽力终止在途任务，不承诺退回已产生费用。进程重启将失去凭据的任务标记interrupted，不保存Key来恢复调用。请求启动采用幂等标识，防止重复点击造成双重计费。

## 5. 费用和质量如何合并

统一报告包含两份独立成本对象：

- benchmark_cost：本次测试实际观测的用量，按选定报价计算的费用；网关自报费用、账单核对费用另列。
- workload_estimate：用户业务用量对应的预算，与测试用量无默认比例关系。

15项测试含长上下文、并发和重复问答，它们不是业务抽样。禁止默认使用“本次评测平均成本×业务请求数”预测月费。后续允许用户选择有代表性的业务样本，仅在明确采样方式和假设后推算。

报告概览并列显示质量表现、延迟/稳定性、本次测试估算费用、业务月预算、证据覆盖，不把便宜折算成质量加分。质量异常保留成本事实，但限制“同模型价格差异”的解释；显示样本观察和方法边界，不把黑盒测试结果写成底层模型身份证明。

重新计算预算无需再次调API；报价更新创建新的分析版本，保留原测试事实和旧分析。对比质量结果时需要相同评测协议、题集/基线版本、设置与足够接近的条件；不满足则并排展示但不排名。

## 6. 模块和接口建议

将Studio建立为唯一活动源码目录（例如studio/），先比对线上版本再迁移；`_websit/server-current`保持档案属性。

```text
studio/
  bench/                  # 已有测试、评分、调用适配
  cost_core/              # Decimal、报价、计费、适用性、比较、报告
  observations/           # 线程安全采集、规范化与持久化
  runs/                   # 计划、执行状态、限额、事件
  reports/                # 联合报告、分析修订、权限与分享
```

拟议接口：GET /api/pricebook/version；POST /api/cost/estimate（不接Key、不调用模型）；POST /api/runs；GET /api/runs/{id}与事件流；POST /api/reports/{id}/cost-analyses（只重算）；POST /api/reports/{id}/shares（显式分享）。保留/api/benchmark兼容适配，避免一次重写所有入口。

价格发布仍由Git/飞书审核管理；主站和Studio消费同一不可变价格版本。Studio运行中固定版本，更新失败继续使用最近已校验版本并标示时效，不清空为零报价。第一期无需主站调用Studio跨域API，只需链接跳转。

预算输入通过同源API交给服务端计算，因此不能继续展示“全部计算只在浏览器完成”。默认临时处理、不记录请求体；只有用户选择保存才持久化业务用量。未来确有离线需求再评估浏览器实现，并保留跨实现一致性验证，不能预先养两套引擎。

现有随机报告ID和公开历史列表不是私有权限体系。新用户任务先使用受保护的会话归属，读取/重算/取消均验证归属；Key不用作身份标识。分享提供可撤销、可过期的脱敏副本或访问授权。主站若展示评测摘要，只展示经用户显式公开且经过适当审核的记录，不自动抓取私有历史。

## 7. 实施顺序与验收

1. **确认源码与事实层**：对比线上、建立活动源码；添加观测schema、线程安全请求记录、unknown状态和一次done。质量评分保持兼容。
2. **Studio预算模式**：重写简单按量核心及黄金算例，提供无需Key的/cost，明确报价和用量假设。
3. **合并现有测试报告**：利用原测试请求出本次费用、覆盖率和可选业务预算。核心验收：开启费用分析不增加任何推理请求，质量结果不变。
4. **执行与私有报告完善**：受限任务、幂等启动、断连查询、取消/重启语义、访问控制及分享；在公开综合模式前完成。
5. **主站打通**：导航、平台深链、旧/cost兼容、共享价格版本；错误offer不跳到别的报价，链接不含秘密。
6. **扩展比较与套餐**：同工作负载多报价，再扩展明确规则的套餐，最后按需建设真实账单对账。

第一轮闭环：从主站某平台进入Studio → 预选报价 → 无Key算预算 → 用户主动选择质量或综合测试 → 一次输入接入配置 → 原测试执行 → 同一报告显示质量、测试费用、业务预算及证据 → 更改预算无需再次测试。

验收还包括：缺usage不显示免费；并发请求不漏记不重复；失败请求保留扣费未知；重新计算不重发POST；旧报告不伪造成本；价格更新可复算旧分析；预算模式不要求Key；私有报告不可由他人枚举读取；服务器计算失败不掩盖已经完成的质量结果。
