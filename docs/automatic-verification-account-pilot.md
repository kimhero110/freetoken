# 自动核验与账号白名单试点

## 已确认范围

用户选择白名单试点：逐站启用。当前没有实际注册账号、提交个人资料或创建第二个机器人。先完成公共来源核验改造；账号执行器须在指定服务商、完成资料配置之后接入。

## 本轮代码

- 来源读取最多尝试三次，只对超时、连接故障及 429/指定 5xx 重试；URL 安全策略拒绝不重试。
- 与最新批准记录匹配、且正式额度仍一致：verified_unchanged。已拒绝记录不作为核验通过依据。
- 来源失败：fetch_failed；不改为资源失效，不更新人工审核日期。
- 核验结果进入现有 automation-state 运行账本，由监控服务提供逐平台结果；中文/英文列表及详情分别显示自动来源核验与人工记录。
- 来源重新抓取后与过时候选哈希一致：24 小时后可生成新的候选版本，复用原提取结果，保留 supersedes，不携带旧批准；发布器仍只合并候选文件。
- 监控服务向现有审核机器人投递最新候选卡片，持久化发送状态、有限重试、按候选版本去重；按钮仍需管理员点击。
- 来源实际变化依然走带费用预算和不确定调用保护的提取流程，不绕过已存在的付费调用保护。

## 明确限制与下一阶段

1. 本轮不把 LLM 的“没变化”作为自动批准依据。现有提取字段不足以覆盖所有权益条款，仍使用完整来源哈希。导航等文本变化仍可能产生审核任务。
2. 仅已配置 source_urls 的平台可自动检查，缺来源的平台显示未知；不会伪造全目录核验覆盖率。
3. 抓取到登录墙、风控页时，不应宣称账号权益有效。账号适配器需识别页面状态、余额和权益，不只检查 HTTP 200。
4. 候选刷新在定时任务运行后生效，并受现有费用窗口与任务健康监控约束。旧卡片仍可能过期；新卡片必须重新审核。
5. 后续应增加结构化关键条款证据（金额、单位、周期、地区、实名/绑卡、过期规则），通过人工标定样本回归测试后，才放开非实质页面变动的自动放行。
6. 待审版本归档与清理需作为单独的可审查事务实现，目前保留历史候选，通知扫描超过 100 个候选时明确报错。

## 白名单账号试点设计

使用 config/account-pilot.example.json 作为空模板。实际资料保存在仓库外的受控目录；仓库只保存模板、适配器和脱敏证据。不能将 .gitignore 视为加密或访问控制。

- 基本档案：真实姓名（确有需要时）、联系邮箱、手机号引用、地区、个人/组织身份、用途、语言/时区。每个服务商只提交实际必填字段。
- 私密引用：密码、邮箱登录授权、API Key、会话凭据存入操作系统凭据库或专用密钥服务。配置里仅保存引用，不存明文。
- 身份验证：不在本项目保存身份证、人脸材料或验证码；人脸、短信、CAPTCHA 等需要人完成时，暂停该站任务并通知你直接操作官方页面。
- 白名单：服务商官方域名、注册入口、允许跳转的身份域名、允许提交的字段、最大账号数 1、允许行为、授权时间和适配器版本。
- 支付：自动付款、充值、绑卡、开启自动续费默认关闭；不因免费试用注册隐式扩大到付费操作。

状态流：发现 → 待启用白名单 → 检查已有账号 → 注册中 → 等待人工/注册成功 → 权益读取 → 有预算约束的最小 API 实测 → 定期检查。

注册提交和 API 调用是不同事务。提交后连接断开时进入“结果待确认”，先检查账号是否已建立，不自动重复提交。人工任务超时保持待处理状态，不假装完成。

## 独立飞书机器人

与内容审核机器人使用不同 App ID、密钥、消息账本和进程。仅允许管理员身份处理人工接力，不拥有内容发布权限。

卡片显示：服务商、任务编号、当前步骤、所需操作、有效时间。按钮为“打开官方页面”“我已完成，继续检查”“取消该任务”。“我已完成”只触发重新检查服务商状态，不直接判定注册成功。

通知失败采用持久化 outbox 和有界退避；展示未送达状态。消息不包含密码、API Key、会话 Cookie 或身份材料。入口必须绑定白名单官方域名，禁止网页内容提供任意回调地址。

## 账号检测证据

分开保存且分开展示：

| 证据 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 公开条款 | 官方当时声明的额度和条件 | 每个账号必然获赠 |
| 账号权益 | 该账号当时的余额、权限、到期日 | 所有地区/新用户一致 |
| API 实测 | 指定账号、模型、端点当时调用成功 | 模型绝对真实、未来持续可用、请求一定免费 |

有效性结论应包含账号适用范围、采样时间、模型/端点、免费余额与付费余额的区分。若无法确认扣费来源，标记“调用可用，免费属性未确认”。真实模型鉴别仍由 Studio 探针独立给出统计证据。

## 启用所需输入

- 首个试点服务商和已存在账号清单，避免重复注册。
- 专用邮箱及需要提交的基本资料（在受控本地档案中填写）。
- 独立飞书应用配置与管理员绑定。
- 单次/每日实测上限以及允许使用的免费额度；默认自动付费上限为 0。

## 验收

先用模拟服务商验证注册幂等、暂停恢复、人工任务过期、消息失败、账号封禁、余额未知、API 失败与免费额度耗尽。再在单一白名单服务商进行真实联调；成功后逐站扩展，不做通用批量自动注册。
