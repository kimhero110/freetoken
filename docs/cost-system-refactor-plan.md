# WitKit 成本系统重构方案

日期：2026-09-06。状态：设计方案，尚未实施。适用范围：D:/Project/token 旧比较器、FreeToken 成本页面及后续 Studio 成本观测。

评审更新：用户明确成本功能应以 Studio 为主。产品归属、正式引擎语言和实施顺序以 [Studio 成本融合评审](studio-cost-integration-review.md) 为准：成本核心优先作为现有 Python Studio 的纯函数包，主站不再维护独立正式计算器。本文的数据契约、计费规则、未知状态、比较和验收原则继续有效。

## 1. 产品目标与首版边界

回答三个独立问题：按我的工作负载预计花多少钱；哪些报价在相同条件下可比较；实际调用观测与估算差在哪里。

首版支持文本 API 按量计费：未缓存输入、缓存读取、显式规则的缓存写入、输出，固定币种，以及已确认适用的货币抵扣。首版完成同模型多报价比较、明确的未知状态和可复算报告。

API 套餐、阶梯、跨月结算和多模型共享额度作为后续独立能力交付。聊天订阅的消息额度、滚动窗口和 API Token 不是同一个计费产品，不做默认兑换。图片、音频、搜索和工具调用在规则实现之前标为未覆盖，不能显示完整总价。

不交付统一性价比分、全自动选路、自动扣费或对任意网关实际账单的保证。

## 2. 现有实现的处置

| 资产 | 处置 | 原因 |
|---|---|---|
| token/src/models.py | 以适配器读取，迁移到新契约 | float 金额、含糊额度单位、月平均负载及布尔适配结论不足 |
| token/src/calculator.py | 替换计费、选型和排序逻辑 | 先按单价和选模型；币种直接排序；按比例推算 Token 抵扣；不适用费用用 infinity 表达 |
| 旧价格数据 | 逐条迁移并复核证据 | 可读取不代表可靠；不自动赋予已审核状态 |
| site/src/lib/cost-engine.mjs | 保留为兼容基线及黄金算例来源，新包替换生产入口 | 已有 BigInt 精确基础运算，但价格仅六位小数、维度固定，没有套餐和时序规则 |
| site/src/lib/pricebook.mjs | 替换成版本化 schema 校验及语义校验 | 平台+模型唯一键容不下区域、档位、有效期等不同报价；高低峰结构被固定 |
| CostCalculator、CostLink、ToolPaths | 保留站点入口及样式，改用新结果契约 | 页面与计算分离，避免重新造站点 |
| 飞书/PR 候选审核 | 复用审核入口，新增价格候选契约 | 平台候选格式不能直接当价格规则使用 |
| Studio | 后续接观测适配器 | 不让评测服务形成第三套计费公式 |

旧代码额外问题：unit_cost_per_1m_tokens 被声明成 property，却定义可变用量参数，调用方无法按普通方法传入真实用量；rank_by_dimension 在筛选兼容方案后，其限流、上下文布尔项基本都是常量，不能表示实际差异。两者删除并用显式指标代替。

## 3. 一套引擎，多个入口

建议在 freetoken 仓库新增 packages/cost-core，使用可同时运行于浏览器与 Node 的 TypeScript 纯函数。复用现有 JavaScript/BigInt 技术基础，不在 Python、浏览器、Studio 分别实现正式算法。

目录建议：

```text
packages/cost-core/src/
  contracts/       # 输入输出类型、schema 版本
  decimal/         # 十进制、货币、单位、舍入
  normalize/       # 厂商 usage → 标准计费维度
  eligibility/     # 模型、上下文、限流、区域等条件
  metering/        # 按报价规则生成计费数量
  billing/         # 价目、阶梯、额度、固定费与结算
  comparison/      # 可比较性、排序、情景敏感性
  reports/         # 分项账、证据、版本与解释
  index.ts
schemas/cost/
data/pricing/      # 审核后的版本化报价
tests/cost/golden/ # 人工独立推导的输入与期望
scripts/pricing/   # 导入、校验、差异和迁移
```

依赖方向：页面/CLI/Studio适配器 → cost-core；cost-core 不访问网络、数据库、系统当前时间或密钥。时间、汇率、价格版本均由调用方传入。Python 旧程序通过批量 JSON CLI 调用 Node 引擎；若此方式不适合部署，再加内部服务，不能复制算法。

暂不建设微服务集群、通用规则脚本解释器或复杂优化平台。先采用有限枚举规则和显式处理函数；不支持的规则返回 unsupported，不执行价格数据中的任意代码。

## 4. 核心数据契约

| 对象 | 必要内容 |
|---|---|
| ModelSpec | 提供商、精确模型版本、能力、输入/输出/总上下文限制、别名映射及证据 |
| Offer | 独立 offer_id、平台、端点类别、模型、API或订阅产品、区域、服务档位、币种、计费规则及有效区间 |
| PriceComponent | 维度、单位、十进制单价、适用条件、计量口径、舍入范围、证据引用 |
| Workload | 时间区间及时区、按模型/任务分组的用量、输入输出与缓存、峰值/上下文需求、观测或假设来源 |
| RequestBucket | 在同一报价规则下可聚合的一组请求、时间段、上下文档位、数量及统计粒度 |
| Entitlement | 金额或数量额度、适用模型/维度、是否共享、刷新/到期时间、抵扣顺序、资格、禁止超额等规则 |
| FXSnapshot | 原币种、目标币种、明确换算方向、十进制汇率、日期、来源 |
| Evidence | 来源类别、URL或受控证据引用、取得时间、生效时间、复核期限、审核状态 |
| Observation | 请求与返回模型、标准化 usage、样本配置、时间、网关自报费用、字段适配器版本 |
| CostReport | 计费分项、抵扣分项、原币金额、换算金额、适配判断、未知原因、假设、全部版本 |

金额与单价在 JSON 中均使用十进制字符串；内部用 BigInt 系数和明确的小数尺度。乘除使用明示精度与舍入策略，禁止中途转换为 Number。Token 数量必须为非负整数，超出安全整数范围时使用整数字符串。不得通过无限小数截断模拟真实结算。

精度上限是版本化配置，输入超限报错而非静默截断。计算精度与界面显示精度分开；厂商按请求、日或月舍入时，只在对应边界执行。舍入规则未知时声明估算假设，不声称精确账单。

报价不可用 model_id 作为唯一键。不同区域、服务档位、上下文档位和有效时间必须可并存。别名的解释固定到本报告的价格快照，历史报告不追随 latest 自动改变。

### 结果状态

不要把所有不确定性压成一个状态或评分：

- calculation_status：complete / partial / uncomputable / unsupported。
- eligibility_status：eligible / ineligible / unknown，保留每个条件的理由。
- evidence_status：来源、审核状态、是否超过复核期限分别保存。
- comparison_status：comparable / conditional / not_comparable，说明分组和缺失条件。

known_subtotal 可以展示已经算出的分项；total 在缺失必需费用时为 null。null 不是零，禁止用 infinity 表示不适用。unknown 也不是免费或支持。

## 5. 标准计费流水线

1. 校验输入及 schema，拒绝负数、错误单位、无效有效区间、互相矛盾的缓存数量。
2. 选择报价快照，按模型、地域、时段、档位和任务类型匹配报价；重叠冲突不能随机取第一条。
3. 检查适用条件。按明确的峰值需求检查 RPM/TPM/并发，月平均只作信息；缺失峰值返回未知。RPD、输入长度、输出上限、总上下文分别核对。
4. 用版本化厂商适配器规范 usage。cached_tokens 是否包含在 input_tokens、推理 Token 是否已包含在输出，由适配器决定，防止重复扣除或重复计费。
5. 将用量分配到时间、上下文或计量档位。只有不会改变计费结果的请求才可聚合；月总量不足以解析逐请求档位时，要求分桶或返回情景估算。
6. 计算原币种分项费用。对于明确采用包含缓存输入口径的简单报价：C = (I-H)×Pin/U + H×Phit/U + O×Pout/U，U 为报价单位。此公式不是全部厂商的通用公式。
7. 按报价声明的计费阶段处理额度与折扣：数量额度可能在计费前改变计量，货币额度可能在计费后抵扣；固定费是否可抵扣必须显式声明，不能统一先加月费再减余额。
8. 在对应结算边界舍入，并处理最低收费及已支持的税费规则。未支持的附加费用明确列为未覆盖项。
9. 生成原币分项账；有可用 FX 快照时再换算展示和比较。FX 展示换算不改变原币结算，也不假设不同币种余额可以互相抵扣。
10. 生成可比较性结论与排序，输出解释、假设和版本。

### 关键规则

- 免费额度按有效期及刷新周期使用，不能把每日额度直接乘天数抵扣任意月度高峰用量。
- Token 包明确区分输入、输出、总量或加权计量；规则未知时不能按用户输入输出比例推算抵扣。
- 多模型共享余额全局只能扣一次；跨请求的余额先后使用需要时间顺序或明确分配规则。只有聚合数据时，给出具名情景，不能悄悄采用最省钱分配。
- 区分逐档累进阶梯与达到阈值后全量改价；不同规则使用独立测试。
- 不允许超额的套餐返回未覆盖用量与 ineligible，不能给出看似可完成任务的低总价。
- 订阅月费、年付摊销和本月现金支出分别展示；付费充值获得的余额要区分存量余额与购买成本，不能把购买成本和余额消耗重复记为费用。
- 折扣和免费额度必须声明能否叠加、作用对象及顺序；拒绝未定义的规则组合。

## 6. 正确的比较与选择

默认固定用户指定的精确模型和完整工作负载。对每个匹配报价计算完整成本，再筛选、换算、排序，不先按输入价与输出价之和选模型。

首版比较同一模型版本、任务能力和相同用量；不同模型可以展示平行结果，但不能只因便宜就自动替换。若用户显式允许替代模型，列明候选集合和能力约束，结果标为条件比较。

完整且适用的方案进入默认成本榜；未知条件、未覆盖费用、过期证据分别列在待核对区域。不同币种无汇率时分组展示。免费基线为零时比较金额差，百分比为不适用。

多模型组合和共享额度会使各模型独立最优失效。第二期先支持用户指定分配的完整估算；如需要自动组合优化，应另立需求，明确目标、约束、组合规模上限及最优性保证，不把简单逐项最便宜宣传为全局最优。

敏感性分析采用显式低/中/高用量或缓存情景，报告每个情景的输入假设。没有概率模型时，不把情景区间叫置信区间。

## 7. 价格治理与报告可复算

价格流程：抓取/人工录入 → 未审核候选 → schema及语义校验 → 展示规则与费用影响差异 → 飞书审批 → PR检查 → 正式价格版本。抓取器输出不能直接覆盖生效报价。

语义检查至少包含单位、币种、来源、有效期、档位冲突、缺失维度、允许的规则组合。复核日期与生效日期不同；复核逾期不能自动删除历史报价或假装仍是当前价格。

每份报告保存 workload 快照、offer及规则版本、pricebook版本、FX快照、engine版本、schema版本、显式计算时间和舍入策略。用规范化输入计算标识；哈希用于识别版本，不作为真实性证明。重算旧报告和按最新价格重新估算是两个操作。

结果包含数量、单价、费用、抵扣原因、未覆盖项和来源。相同输入及版本必须输出相同结果。

## 8. 网站与 Studio 的边界

主站 /cost 无需 Key、本地计算。基础模式提供用量预设；专业模式提供逐维度或分桶输入。结果展示原始费用、适用抵扣、预计支出和费用覆盖范围；月费产品显示固定费用，零用量不强行等于零费用。

平台页带 offer_id 或平台筛选进入计算器；不在 URL 中携带 Key。公开分享只包含用户明确选择的脱敏用量与报价参数。

Studio 只将调用观测传给同一引擎。报告分开展示按报价估算、网关自报费用和账单核对费用；调用成功不证明报价准确或模型身份真实。任务默认不重复执行计费 POST。真实调用入口的鉴权、限额、日志及持久化需在该阶段单独验证。

历史实测默认私有；只有明确分享的报告可公开，支持撤销和到期。任何价格候选、飞书、Git、报告或客户端错误日志都不得含用户 API Key。

## 9. 验收矩阵

| 类别 | 必须通过的独立算例 |
|---|---|
| 加权成本 | 输入1M、输出10M，A=(1,8)、B=(6,4)，必须得到81与46并选择B |
| 精确金额 | 微小单价与大量Token、不同小数尺度、舍入边界；结果由独立十进制参考值核对 |
| 零与未知 | 零用量、免费报价、正用量缺价、缓存零用量缺价；分别符合状态定义 |
| 缓存/推理 | 总输入包含缓存、字段重复、缺失维度、缓存大于输入，禁止双重计费 |
| 币种 | USD与CNY无FX不混排；有FX保留原币及快照；无效/零汇率拒绝 |
| 额度 | 到期、每日刷新、首月赠金、模型限定、抵扣上限、余额不足且禁止超额 |
| 共享额度 | 多模型只抵扣一次；请求顺序改变时按声明规则产生可解释结果 |
| 时段/阶梯 | 跨日跨月、时区边界、上下文阈值、累进与全量阶梯分开验证 |
| 适用性 | 未知限流不判通过；月平均低但峰值超限不判适用；分别检查上下文和输出上限 |
| 兼容迁移 | 旧数据不丢失原值和来源；不支持规则隔离，不能静默自动修正 |
| 可复算 | 同版本同输入完全一致；最新报价更新不改变旧报告 |
| 页面 | 页面费用与CLI一致；部分结果不显示完整总价；键盘、移动端、错误信息可用 |

除了固定黄金算例，还验证有明确前提的性质：无折扣阶梯的线性报价满足可加性；固定线性报价下用量增加不降低原始费用；适用余额增加不提高应付费用；抵扣不超过适用费用。同样性质不能盲目用于全量阶梯或最低收费。

黄金预期由人工公式或独立参考实现生成，不能让待测引擎自己生成期望。测试通过数量不是上线标准，关键计费语义全部有证据和边界算例才是。

## 10. 分阶段实施与退出条件

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| A：审计与冻结 | 行为清单、报价盘点、旧算法反例、支持范围和schema草案 | 每条旧规则都有保留/修正/不支持决定；旧榜单不作为可靠推荐继续推广 |
| B：可信按量核心 | contracts、decimal、usage适配、线性计费、eligibility、报告 | 第一批黄金算例通过；输入未知时不产生伪精确总价；Node和浏览器一致 |
| C：报价比较与治理 | 多offer、FX、价格候选审核、比较解释、迁移器 | 原币正确、报价冲突被拒绝、旧数据迁移有审计、回退价格版本已演练 |
| D：主站接入 | 替换/cost引擎、场景预设、平台入口、完整/部分结果UI | 老页回归通过，手机可用；明确的版本切换及回滚记录 |
| E：套餐规则 | 固定费、周期额度、共享余额、时段/阶梯 | 每个新增规则独立验收；不支持组合继续明确拒绝 |
| F：Studio观测 | usage适配、样本估算、费用证据、私有报告 | 一次授权真实调用可从用量追溯到每项费用；不把估算冒充扣费 |

先交付 A–D，形成可上线的完整 API 预算与比较工具。E、F 分别发布，避免把首版拖成所有计费产品都支持的大工程。工期在A阶段完成数据和规则盘点后估算，按范围与验收门槛推进，不承诺未经盘点的固定天数。

## 11. 迁移、发布与回滚

旧比较器进入维护状态，保留原数据和独立版本标签。迁移先dry-run，输出字段映射、缺失字段和被隔离记录；导入必须幂等，禁止用默认零补齐缺价或缺额度规则。

新旧双算用于发现差异而非要求一致。每个差异归类为已知旧缺陷、规则变化、数据差异或新缺陷；未解释的关键差异阻止上线。首批选少量报价及真实代表用量，完成验收后扩大覆盖。

主站新旧入口通过配置切换，不覆盖历史报告。回滚绑定引擎版本、schema和价格快照，不能只回滚页面。若旧引擎存在已知错误，回滚到最近验证版本或暂时关闭比较，不恢复有误榜单。

运行观测记录匿名错误类别、unsupported规则、缺价和状态计数。目标是没有未解释的费用差异、没有未知作零、没有重复额度抵扣；不收集密钥和用户原始业务内容作为诊断数据。

## 12. 本方案的完成定义

第一阶段上线成立，当且仅当：每个展示金额可追溯到数量、报价、规则与版本；缺失信息有明确状态；默认比较具有一致模型、用量与币种口径；额度不凭空假设；历史报告可复算；网站和后端使用同一正式引擎；旧算法反例均有回归覆盖；发布和回退可执行。

真实账单精确一致不是纯预算引擎的无条件承诺。只有计费维度、结算规则、用量证据和账单对账都齐全时，才能给出对应范围内的对账结论。
