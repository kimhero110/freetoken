# 成本探针与 FreeToken 整合建议

日期：2026-09-05。性质：方案建议，尚未实施。

依据：`D:/Project/token/docs/route-a-cost-probe-design.md`、token 的成本引擎与数据模型，以及当前 FreeToken 的 Astro 站点、候选审核和能力探测实现。未检查 test.witkit.zone 的服务端源码与线上部署；原文对质量评测系统和共享 worker 的描述仍是待核实条件。

## 建议结论

支持整合，定位为“按我的用量选平台、看预算、核验接入”。先把可信预算计算接到现有平台页，再上线可选的真实调用。将公共价格治理放在 FreeToken，用户密钥和实时任务放在独立执行环境。原 Flask 比较器的页面和抓价入口不直接搬入生产。

FreeToken 负责发现与比较，WitKit Studio 负责按需测量；商业推荐必须与排序规则分开。首版不推出统一性价比分，不承诺通过黑盒测试确认底层模型身份。

## 原方案需要先修正的定义

1. **列出模型不等于调用成功。** `/models` 结果标为 `listed`；对指定操作发送真实请求并验证协议后才标为 `call_succeeded`，同时记录日期和所用凭据作用域。未抽测模型保持未测；返回 404 不直接判定整个端点不可用，允许用户指定模型。模型列表通常只有基础信息，见 [Models API](https://platform.openai.com/docs/api-reference/models/object?lang=curl)。
2. **网关自报费用不是独立核验的扣费。** LiteLLM 文档展示的是响应头 `x-litellm-response-cost` 的计算费用，并非统一 `usage.price` 单价字段，且其价格来自成本表和配置。每种网关需要版本化适配器；无法解释单位、币种和字段语义时保留原始值，归为 unknown。见 [LiteLLM Spend Tracking](https://docs.litellm.ai/docs/proxy/cost_tracking)。
3. **一次样本总费用推不出输入和输出两项单价。** 即使费用字段可靠，也只有 `C = Tin × Pin + Tout × Pout` 一个方程。记录 sample_cost，不凭一个值构造两项每百万价格。缓存、阶梯价、折扣和最小计费单位会进一步改变关系。
4. **质量异常不应删除成本事实。** 保留已经观测或对账的费用；将“按声明模型比较官方价”的结论置为不可比。快照通过只能写“本次样本未发现异常”，不能写“已确认真实性”。
5. **token 差异不直接等于偷计费。** 需要匹配模型版本、tokenizer、消息模板和工具等输入。即使官方计数接口也注明结果是估计值、与实际 usage 可能略有差异。先展示差异与待解释项；移除统一 10%/30% 定罪阈值。见 [Claude Token Counting](https://platform.claude.com/docs/en/build-with-claude/token-counting)。
6. **价格、可用性与身份分开核验。** `live` API 调用成功不能把价格自动提升为已核验。第三方端点即使返回官方 model_id，也只能用官方价做参考基线，不能当成该端点的实际收费。

## 推荐的产品流程

平台详情页“估算我的成本” → 输入月用量与使用方式 → 选择相同模型/工作负载 → 查看原币种与统一币种估算、价格来源、核验日期、适用免费额度 → 可选“用我的接入点验证” → 明确选择模型与请求预算 → 查看调用观测和条件化比较。

免费额度展示应提前到第一阶段，这是与 FreeToken 现有用户最直接的连接。区分 API 抵扣金、每日额度、注册赠送、订阅消息额度；不同单位不能自动混算，未知资格、过期时间或使用规则时不直接扣减成本。订阅与 API 也不能假定可互相兑换。

首版结果分别展示：月预算估算、额度适用条件、端点调用状态、证据覆盖率。价格缺失的模型不进入完整成本排名；官方参考成本为零时溢价率无定义，不能除零或标为无限差。

## 架构与归属

| 部分 | 放置位置 | 整合方式 |
|---|---|---|
| 公共模型与价格登记 | FreeToken `data/pricing/`（新增） | 独立 schema，关联 platform_slug；不要塞进现有 free_quota |
| 价格候选与审核 | 既有候选/飞书/PR 流程 | 增加 price_update 类型、差异审查、快照哈希与编译产物；不自动提升正式价格 |
| 成本计算 | 新建纯函数模块 | Decimal 运算、显式币种、FX 快照、计费规则和未知状态；不依赖 Flask 或网络 |
| 预算界面 | Astro `/cost` 与平台页入口 | 无 Key 即可用；客户端十进制实现与服务端共享黄金算例，避免两套公式漂移 |
| 真实 API 调用 | WitKit 执行服务（待检查）；否则独立受限 worker | 复用协议/HTTP 保护逻辑，隔离用户密钥和任务；不能由静态 Astro 页面承担服务端执行 |
| 历史与分享 | 执行服务的脱敏报告存储 | 默认私有；分享显式生成、可撤销、可过期，不带 Key、原始账号信息或任意响应头 |

公共情报和用户测量不要走同一数据通道：公共价格通过 Git 审核发布；用户 Key 不进入 Git、GitHub Actions inputs、飞书、报告或构建日志。个人一次探测结果不能自动更新全站登记价。

仅在检查 WitKit 现有 worker 的任务状态、鉴权、日志与存储之后，才能承诺复用它；当前 FreeToken 仓库里没有该交互式评测后端。

## 建议的数据契约

- `PriceRecord`：provider/platform、模型版本、操作、服务区域与档位、币种、输入/输出/缓存/工具等计费维度、生效日期、到期或复核日期、来源、审核人、价格库版本。数字用十进制字符串持久化。
- `UsageProfile`：按模型分配的月用量、输入与输出、缓存假设、单次上下文分布；峰值 RPM/TPM 与月请求数分别记录，不能用月平均推出峰值可行性。
- `Observation`：endpoint 标识、请求模型、返回模型、操作、listed/call_succeeded/failed/untested、时间、usage、请求 ID、适配器版本、请求配置摘要。仅保留允许列表内的响应字段。
- `PriceEvidence`：`source_kind` 为官方价目/网关自报/用户填写/账单；独立记录 `verification_status` 为未核验/已核对/已对账。来源类别不强行排成单一高低等级。
- `CostReport`：estimated_monthly_cost、observed_sample_cost、reconciled_cost 分离；固定 pricebook、FX、公式与规则版本，并保存估算假设。未知金额与缺汇率必须允许为 null，不能默认 0。

账单对账可以提高证据强度，但首版不要求用户交出管理员密钥。可后续支持脱敏账单导入或特定平台只读对账适配器。

## 旧成本引擎的实际复用程度

可以参考 Usage 的概念、基础按量公式和套餐实体；核心计算应重构后迁移。

| 已读代码中的问题 | 对整合的影响 |
|---|---|
| `src/models.py:14` 等使用 float，没有 Decimal/FX 实现 | 文档中的 Decimal + FX 是建设目标，不能当成现成资产 |
| `src/calculator.py:63` 按输入价+输出价选模型 | 忽略输入/输出比例；也忽略套餐额度规则，可能选择更贵方案 |
| `src/calculator.py:195` 直接按 total_cost 排序 | 未统一币种，跨币种排序无效 |
| `src/models.py:78` 以月请求数除整月分钟数 | 得到平均负载，不能据此宣称不会触发分钟限流 |
| 缺失上下文/速率限制被视为满足 | 新模型需区分 unknown 与 supported |

本地无网络复现（假设价格，不是任何真实厂商报价）：A 输入1、输出8；B 输入6、输出4；输入1M、输出10M。旧算法因 1+8 < 6+4 选择 A，实际算得 A=81、B=46。故 `_select_model` 不宜原样复用；应该计算完整用量及规则下的每个候选总成本，再在满足要求且证据足够的候选中排序。

## 分期建议与验收

### 第一期：可信预算工具

新增少量人工核验的价格记录、Decimal 核心、相同模型比较、免费额度条件展示、`/cost` 与平台页入口。海外官方价目也可以用于离线估算，无需先建设海外 API 出口；实际可调用性单独标注。

验收：汇率缺失不跨币种排序；unknown 不等于免费；模型按加权成本正确选择；价格过期有提示；历史报告可用固定版本重算；缓存、零用量、无基准价格等边界有黄金算例。价格记录必须经过既有审核流程。

### 第二期：可选的受控调用

从少量固定官方端点及一个已验证网关适配器开始。模型列表与调用观测分离，用户明确选择最多若干模型，一次一个受限样本，不重试计费 POST。公开入口需要身份/任务配额、并发与总执行时间限制；先完成这套运行治理，再开放任意 base URL。

复用 `scripts/safe_http.py` 的 HTTPS、公网地址检查、DNS 固定连接、受认证请求禁止重定向、响应体上限；当前非流式客户端只测总延迟，不把总耗时当 TTFT。若需要 TTFT，另做有总时限的流式客户端。请求数量和输出 token 上限只能限制请求规模，不能向不可信网关承诺绝对账单上限。

### 第三期：质量联动与对账

核实质量探针的误报率和证据范围后再关联；增加网关专用费用解释、账单对账、A/B 报告。共享质量调用只在 endpoint、模型、参数、身份作用域与观测时间均匹配时复用，不能拿历史其他 Key 的测试替代当前结果。

暂缓统一性价比总分、自动跨平台调度、订阅套利、默认公开用户报告以及首版 Worker 跨境代发。商业入口可以存在，但不影响默认排序，并明确推荐关系。

## 尚需核实

WitKit Studio 服务端仓库与部署架构、任务鉴权与队列、质量探针的真实证据、用户报告的存储规则。原文 5–7 天覆盖真实探测、历史分享、鉴权限额、价格治理和质量联动的工期，在这些条件未核实前不宜作为交付承诺。
